# Bronze to Silver processing

Run from the repository root using the project environment.

Local input (no SeaweedFS connection):

```powershell
python -m src.processing.main --input data/articles.json --local-only
```

Read the current Bronze snapshot from SeaweedFS and publish Silver:

```powershell
python -m src.processing.main
```

Without `--input`, reads `s3://news-raw/aljazeera/articles.json`.
Local outputs default to `data/processed/`: `processed_articles.json`, `rejected.json`, and `report.json`.
Uploads use the prefix `aljazeera/silver/` in `news-processed`.
Bucket names can be overridden with `SEAWEEDFS_RAW_BUCKET` and
`SEAWEEDFS_PROCESSED_BUCKET`; connection settings match the scraper.
Provision buckets first using the existing data lake initializer.

The scraper currently writes a cumulative snapshot. Each processing run rebuilds
Silver from that snapshot; it does not append or maintain a cross-run hash index.
The first valid occurrence wins for repeated article IDs or normalized body hashes.
Rejected records retain their original payload and a reason.
Published articles contain exactly: `id`, `Link`, `Headline`, `Summary`,
`Full_Content` (paragraph list), `Publisher`, `Topics`, `Sources`, `Date`,
`topic_id`, and `topic_label`. Original Arabic spelling is retained; normalized
text and SHA-256 hashes are internal deduplication values only.
`Date` uses D/M/YYYY, derived from Published_At or a valid Date fallback when
Published_At is absent. Missing metadata defaults to "No Summary", an empty
publisher, and empty Topics/Sources lists. Missing ML fields are null; supplied
ML fields are preserved, not generated by processing.

This first stage implements exact SHA-256 deduplication, not MinHash similarity,
ML inference or warehouse loading. Uploads replace the three
output objects separately; they are not an atomic multi-object publication.


## Cleanup and quality policy

Readable paragraphs have whitespace collapsed; empty and exact duplicate paragraphs
are removed. A paragraph exactly matching Summary after whitespace cleanup is
removed from Full_Content. Arabic spelling and punctuation remain unchanged.
Summary-only bodies are quarantined rather than silently treated as full articles.

Defaults require at least 20 words and 30% Arabic letters among alphabetic
characters. Standalone known error messages are also quarantined. These are
heuristics, not a language classifier: tune them for the corpus, for example:

```powershell
python -m src.processing.main --input data/articles.json --local-only --min-words 30 --min-arabic-ratio 0.5
```

Quarantined records are retained in rejected.json with their original payload and
reason. Accepted article fields remain unchanged. No live upload is required to
review the local outputs.


## Automatic publication

Running `python -m src.processing.main` reads the Bronze JSON snapshot from
SeaweedFS and automatically publishes processed_articles.json, rejected.json and report.json
to news-processed/aljazeera/silver/. A local copy is also saved. No --upload flag
is required; the old flag remains accepted for compatibility.
Use --local-only to skip publication for previews.
Buckets must be provisioned before running. Upload failures propagate as errors.
Processing is not connected to Airflow; the DAG runs scraping only.


## Notebook normalization

Internal NLP/hash normalization follows cell 23 of aljazeera_EDA.ipynb:
remove URLs and mentions, remove hashtag markers, digits, Latin/non-Arabic
characters, selected Arabic punctuation and tatweel; normalize Alef, Ta Marbuta,
and Alef Maqsura; remove NLTK Arabic stopwords. The notebook's unused `txt`
digit assignment is corrected. Arabic diacritics are not explicitly removed.
Whitespace tokenization after punctuation spacing replaces word_tokenize so
processing needs no NLTK Punkt downloads. The Arabic stopword list is vendored
from https://github.com/nltk/nltk_data (corpora/stopwords, Arabic list).
The notebook's 90–310 word EDA filter is not applied. Output fields still retain
readable original text; this normalization changes only matching/hash behavior.
